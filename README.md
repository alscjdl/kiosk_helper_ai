📱 디지털 약자를 위한 키오스크 결제 보조 시스템



1. 프로젝트 소개

고령층 및 장애인 등 디지털 약자들이 키오스크 이용 시 겪는 복잡한 UI와 어려운 용어로 인한 불편을 해결하고자 함. AI 비전 기술로 화면을 분석하고, 생성형 AI를 통해 사용자 눈높이에 맞는 쉬운 안내와 음성 가이드를 제공하는 서비스임.  



2. 주요 기능 및 사용 기술

이미지 인식 분야: 키오스크 화면 캡처 이미지에서 텍스트를 추출하는 EasyOCR 기술과 버튼 및 메뉴 등 주요 UI 요소를 탐지하는 YOLOv8, OpenCV 기술을 적용함.

상황 분석 및 문장 생성 분야: 인식된 정보를 바탕으로 현재 결제 단계를 분석하고, 어려운 용어를 쉬운 표현으로 변환하기 위해 OpenAI GPT API를 활용함.

시스템 통합 및 안내 분야: 사용자 친화적인 웹 인터페이스를 구성하기 위해 Streamlit을 사용했으며, gTTS 라이브러리를 통해 실시간 음성 가이드를 출력함.



3. 팀원 및 역할 분담

• 윤소희: 이미지 인식 및 객체 탐지 모듈 개발. EasyOCR, OpenCV, YOLO를 활용하여 데이터셋 수집 및 라벨링을 수행.

• 조민체: 상황 분석 및 AI 프롬프트 엔지니어링. OpenAI API 연동과 시스템 간 예외 처리, 윈도우 인코딩 호환성 버그 디버깅을 수행.

• 김사랑: UI 제작, 음성 출력 및 시스템 통합. gTTS를 활용한 음성 출력 제어 및 시스템 파이프라인의 최종 통합을 수행.



4. 개발 프로세스 (Github 기반 협업)

1)	사회적 이슈 조사 및 서비스 설계: 디지털 약자의 키오스크 이용 불편 사항을 분석하고 서비스의 핵심 기능을 정의함.
 
2)	데이터 가용성 분석: 키오스크 화면 이미지 샘플을 수집하고 오픈소스 라이브러리 및 API의 실제 적용 가능성을 테스트함.

3)	팀원 역량 분석 및 업무 분장: 기술 스택별 역할을 최적화하여 업무를 분담하고 GitHub 저장소를 개설하여 협업 환경을 구축함.
	
4)	개발 및 버전 관리: GitHub Issue 기반으로 세부 업무를 분담하고, 작업 진행 상황이나 기능 보완 사항이 생길 때마다 해당 Issue 아래에 댓글(Comment)로 피드백을 주고받으며 코드를 안정적으로 병합하고 버전을 관리함.

5)	결과 검증 및 디버깅: 다양한 키오스크 시나리오별 동작성을 검증하고, 개발 환경별 실행 오류 및 버그를 디버깅함.



5. 프로그램 설치 및 구동 매뉴얼

• 저장소 복제 단계: 아나콘다 프롬프트(Anaconda Prompt) 환경에서 git clone 명령어를 활용해 원격 저장소의 소스 코드를 로컬 컴퓨터로 다운로드하고, 폴더 내로 이동(cd kiosk_helper_ai)함.

• 필수 라이브러리 설치 단계: 프로그램 구동에 필수적인 외부 패키지들을 한 번에 설치하기 위해 터미널에 pip install streamlit opencv-python easyocr ultralytics openai gTTS 명령어를 실행함.

• 환경 변수 설정 단계: 프로젝트 최상위 경로에 확장자 없이 .env 파일을 생성하고, 발급받은 OpenAI API 키를 OPENAI_API_KEY=sk-proj-본인의API키값 형식으로 정확히 입력하여 저장함.

• 프로그램 최종 실행 단계: 아나콘다 프롬프트 창에 streamlit run src/app.py 명령어를 입력하여 로컬 브라우저 기반의 웹 인터페이스를 구동함.

• Windows 환경 예외 처리 팁: 윈도우 내부 시스템의 한글 인코딩(cp949) 충돌로 발생하는 'UnicodeDecodeError'를 방지하기 위해, 소스 코드 내 서브프로세스 디코딩 옵션에 errors="ignore" 예외 처리를 반영하여 환경에 구애받지 않고 안전하게 구동되도록 매뉴얼 구체성을 확보함.



6. GitHub 협업 및 코드 기여 규칙

• 브랜치 전략(Branch Strategy): 제품 제출용 최종 완성본을 관리하는 main 브랜치, 팀원별 개별 작업을 진행하는 feature 브랜치(feature/ocr, feature/ai-prompt, feature/ui)로 분리하여 협업의 독립성을 보장함.

• 작업 프로세스 및 참여도 검증: 개발할 기능이나 버그를 GitHub Issue에 먼저 분담하여 등록하고, 각자 작업을 수행할 때마다 세부 진행 상황과 의견을 Issue 댓글(Comment)을 통해 실시간으로 기록 및 교유함. 이를 통해 대면 회의 외에도 온라인상에서 소통하며 교차 검증을 진행하였고, 팀원 개별의 협업 정도와 기여도를 GitHub 기록으로 명확히 남겨 검증 가능성을 높임.
